# 小智 XiaoZhi - 前端技术评估文档

## 一、技术选型

| 组件 | 选择 | 理由 |
|------|------|------|
| 框架 | React 18 + TypeScript | 组件化成熟，生态丰富 |
| 状态管理 | Zustand | 轻量、简洁，适合插件化架构 |
| UI框架 | TailwindCSS + Radix UI | 现代化、定制灵活 |
| 路由 | React Router v6 | 方案成熟 |
| HTTP客户端 | Axios / Fetch | 按需选择 |
| 表单 | React Hook Form + Zod | 类型安全验证 |
| 国际化 | i18next | 社区成熟 |
| 部署 | Vite | 构建速度快 |

---

## 二、功能模块复杂度分级

| 复杂度 | 模块 | 说明 |
|--------|------|------|
| **低** | 导航框架搭建 | React Router + 布局组件 |
| **低** | 静态页面 | 欢迎页、关于页等 |
| **中** | 对话界面 | 消息渲染、SSE流式接收、光标动画 |
| **中** | 插件市场 | 列表、搜索、分类筛选 |
| **中** | 知识库管理 | 文档上传、列表管理 |
| **中** | 智能体管理 | CRUD表单、配置面板 |
| **中** | 设置页面 | 表单配置、主题切换 |
| **高** | 工作区文件树 | 树形组件、语义搜索、文件预览 |
| **高** | 富文本编辑器 | Markdown编辑、代码高亮 |
| **高** | 操作审查弹窗 | 动态渲染、状态管理 |
| **高** | 插件化UI扩展 | 动态加载组件、样式隔离 |

## 三、技术可行性分析

### 可行（已有成熟方案）

| 模块 | 方案 | 说明 |
|------|------|------|
| 对话消息渲染 | 自定义组件 + Markdown解析 | react-markdown / marked |
| SSE流式接收 | EventSource / fetch + ReadableStream | 成熟方案 |
| 文件树组件 | react-arborist / 自定义 | 已有成熟库 |
| 富文本编辑 | @uiw/react-md-editor / TipTap | Markdown支持好 |
| 拖拽排序 | @dnd-kit | 现代化方案 |
| 表格组件 | TanStack Table | 功能强大 |
| 国际化 | i18next + react-i18next | 生态成熟 |

### 有挑战需专项研究

| 模块 | 挑战 | 应对 |
|------|------|------|
| 插件化UI | 动态组件加载、样式隔离 | 微前端方案 or 动态import |
| 复杂状态同步 | 多端状态一致性 | Zustand + SSE实时同步 |
| 大文件预览 | 性能问题 | 虚拟滚动、分片加载 |
| 离线支持 | Service Worker | 渐进式增强 |

## 五、关键风险点

| 风险 | 影响 | 建议 |
|------|------|------|
| 插件化UI动态加载 | 实现复杂度高 | 前期用条件渲染过度，后续引入微前端 |
| SSE流式性能 | 大流量时UI可能卡顿 | Web Worker处理解析，主线程只负责渲染 |
| 多端状态同步 | 状态不一致问题 | 使用Zustand的subscribeWithSelector |
| 浏览器兼容 | Radix UI对旧浏览器支持 | 渐进增强，核心功能降级处理 |
