# 小智 XiaoZhi - 需求及架构文档

## 一、产品定位

### 1.1 产品概述
一款插件化的 Web 版 AI 助手平台，支持通过插件自定义切换底层能力，使其在不同领域可专注于不同业务场景。

### 1.2 目标用户
- **开发者**：需要 AI 辅助编程、代码生成、调试
- **业务人员**：需要 AI 辅助文档处理、数据分析、业务流程
- **企业**：需要统一的 AI 能力中台，支持定制化业务插件

### 1.3 核心价值
- **插件化架构**：核心能力标准化，插件可插拔、可切换
- **多协议支持**：兼容 MCP、A2A 等主流 AI 代理协议
- **记忆与知识**：支持多层次记忆管理、向量知识库、RAG 增强
- **领域适配**：通过切换插件组合，快速适配不同业务领域

### 1.4 设计原则（用户体验优先）

| 原则 | 描述 | 具体要求 |
|------|------|----------|
| **零/低学习成本** | 用户开箱即用，无需培训 | 90%功能3步内可达；提供引导式操作；智能提示覆盖全流程 |
| **UI 简洁明了** | 界面清爽，信息层次清晰 | 核心对话为主；插件按场景自动分组；高级功能折叠隐藏 |
| **功能通俗易懂** | 功能命名清晰，操作符合直觉 | 使用用户语言而非技术术语；图标+文字双重标识；操作结果即时反馈 |
| **渐进式复杂度** | 基础用户简单，高级用户强大 | 专家模式/新手模式切换；高级功能需要时再出现；提供模板和预设 |

## 二、功能需求

### 2.1 UI/UX 设计规范

#### 2.1.1 界面布局原则
| 区域 | 设计要求 |
|------|----------|
| 对话区 | 最大面积，沉浸式体验，消息气泡简洁 |
| 工具栏 | 左侧/顶部固定，图标+文字，可折叠 |
| 插件面板 | 按场景分组，不需要的插件隐藏 |
| 设置区 | 弹窗式而非页面跳转，减少导航层级 |

#### 2.1.2 交互设计要求
- **即时反馈**：按钮点击、状态变化立即响应
- **容错设计**：操作可撤销，危险操作需确认
- **智能补全**：输入提示、下一步建议、快捷操作
- **个性化**：记住用户偏好，首页展示常用功能

#### 2.1.3 新手引导
- 首次使用引导（插件推荐、知识库创建）
- 功能发现：hover 提示、长按说明
- 模板市场：预置常用场景模板（会议纪要、代码review、文档总结）

#### 3.3.4 操作审查机制（类 Claude Code 管理方式）

参考 Claude Code 的操作分级模式：

**操作分级策略：**

| 级别 | 操作类型 | 示例 | 处理方式 |
|------|----------|------|----------|
| L1 - 安全 | 只读操作 | 读取文件、搜索内容、查看目录 | 直接执行，无需确认 |
| L2 - 低风险 | 无破坏性写操作 | 创建新文件、生成代码、编辑已有内容 | 直接执行，事后记录 |
| L3 - 中风险 | 有潜在影响的操作 | 修改配置文件、执行测试 | 执行前用户确认（Once） |
| L4 - 高风险 | 不可逆/危险操作 | 删除文件、执行生产命令、发布代码 | 执行前用户明确审批（Always） |
| L5 - 极高风险 | 系统级危险操作 | rm -rf、系统命令、数据库写操作 | 完全禁止，需管理员介入 |

**审查流程：**

```
用户输入 → Agent规划 → 操作分类 → 审查决策
                                      ├── L1/L2 → 直接执行
                                      ├── L3 → 弹窗确认
                                      ├── L4 → 审批队列等待
                                      └── L5 → 拒绝+告警
```

**用户确认界面：**
- 操作描述（用自然语言解释将执行的操作）
- 影响范围（哪些文件/系统会受影响）
- 可选操作（执行/取消/修改参数）
- 记住本次选择（仅本次生效）

**日志与审计：**
- 所有操作记录到审计日志
- 包含：时间、用户、操作内容、审批状态、执行结果

#### 3.3.5 任务拆分评估与评分选择机制

**任务拆分流程：**

```
用户任务 → 意图分析 → 子任务拆分 → 并行/串行规划 → 执行计划
```

**评估维度：**

| 维度 | 权重 | 说明 |
|------|------|------|
| 可行性 | 30% | 子任务是否可执行（工具支持、权限足够） |
| 成本 | 25% | Token消耗、时间估计、资源使用 |
| 准确性 | 25% | 与原始目标的匹配度 |
| 效率 | 20% | 执行路径最短、步骤最少 |

**评分选择流程：**

```
生成方案A、B、C...
    ↓
各方案多维度评分（0-100）
    ↓
加权计算总分
    ↓
选择最优方案
    ↓
如最优分数低于阈值 → 请求用户确认或重构任务
```

**示例场景：**
用户需求："帮我分析这个项目的代码质量"

| 方案 | 可行性 | 成本 | 准确性 | 效率 | 总分 | 决策 |
|------|--------|------|--------|------|------|------|
| A: 全量代码扫描 | 95 | 40 | 90 | 30 | 66 | 备选 |
| B: 重点模块分析 | 95 | 70 | 95 | 70 | 84 | **最优** |
| C: 只看README | 100 | 90 | 60 | 95 | 83 | 备选 |

## 四、多租户设计

### 4.1 租户隔离模型

| 隔离层级 | 实现方式 |
|----------|----------|
| 数据库 | 独立数据库 or Schema 隔离 |
| 缓存 | Redis Namespace 隔离 |
| 文件存储 | 独立 Bucket/目录 |
| 插件 | 插件级租户可见性控制 |
| API | 请求级租户上下文传递 |

- 租户配置（套餐、限额）

## 八、关键决策确认

| 问题 | 决策 |
|------|------|
| 计费模式 | 按 token 计费（对接外部模型消耗） |

| 私有化部署 | 需要支持，支持离线/私有化部署，方便企业内部使用 |

### 8.1 前端插件说明

前端插件指可插入到主界面的自定义 UI 组件/面板，例如：
- **自定义面板**：天气插件、股票插件、日历插件
- **垂直领域 UI**：CRM 侧边栏、数据预览面板、审批面板
- **交互组件**：文件预览器、代码编辑器、图表组件

实现方式：
- Web Component 标准封装
- React/Vue 组件包格式
- 通过插件注册 API 挂载到指定位置
